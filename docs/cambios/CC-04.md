## Cambio
1. **Nueva variable `VITE_WEB_URL`** (cliente, opcional): la URL pública de la web. La APK la usa para enlazar a `/artesano/registro`.
2. **Alta del perfil con `insert` en lugar de `upsert`.** El alta solo ocurre una vez y `insert` evita sobrescribir el rol. Las ediciones posteriores van por `update`.
3. **El admin resuelve las acreditaciones con la RPC `resolver_acreditacion(artesano, resultado, nota)`.**
   - Ya no edita perfiles ajenos directamente: la política de `update` queda solo para el propio perfil.
   - La RPC rechaza a quien no es admin con `no_autorizado` y exige un motivo para rechazar.
4. **El alta no acepta `acreditacion_nota`:** esa nota solo la escribe el admin.
5. **La sesión se guarda con la clave fija `costearte.auth`**, para que la APK abra sin conexión aunque el token haya vencido.
6. **Archivos agregados a la tabla del PRP 001:**
   - `src/acceso/usePerfil.ts`
   - `src/app/app.test.tsx`
   - `src/compartido/ui/estilos.css`
   - `src/compartido/supabase.ts`
   - `docs/contratos.md`
   - `README.md`

## Motivo
La revisión (hallazgos 1–5) mostró dos tipos de problemas:
- **Criterios que no se cumplían:** el error de rol desaparecía, la sesión se perdía sin conexión, no había forma de cambiar la contraseña y un no admin no recibía error al aprobar.
- **Cambios de contrato sin registro.**

## Impacto
- **Alcance:** sin funciones nuevas para el usuario. Corrige el cumplimiento del PRP 001.
- **Tiempo:** ya implementado en la rama `cu-01/acceso-acreditacion`.
- **Riesgos:**
  - Leer la sesión guardada sin conexión muestra datos que podrían estar desactualizados. Las llamadas al servidor siguen exigiendo un token válido.
